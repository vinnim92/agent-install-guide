AI Agent 安装故障排查

遇到问题了？按下面的错误类型找到对应解决方法

Windows — 双击 .cmd 没反应 / 窗口一闪而过

  • 不要在压缩包预览中运行：请先完整解压 zip 文件到文件夹，再打开文件夹双击 .cmd。在压缩包预览窗口里直接双击会导致脚本找不到同目录的 .ps1 文件。
  • 检查是否解压完整：确保 windows 文件夹里的 .ps1 文件和 .cmd 文件在同一目录。如果缺少 .ps1 文件，重新解压 zip。
  • 右键以管理员身份运行：右键点击 .cmd 文件 → "以管理员身份运行"。
  • 从命令行运行看错误信息：在 windows 文件夹地址栏输入 cmd 回车，然后输入 install-codex.cmd 回车，窗口不会闪退就能看到错误信息。

Windows — 弹出"已保护你的电脑"提示（SmartScreen）

  • 现象：双击 .cmd 或运行脚本时，Windows SmartScreen 弹出蓝色或黄色警告框。
  • 这是正常的安全提醒：因为脚本文件来自互联网（通过 zip 下载），Windows 会默认提醒。
  • 解决方法：点击"更多信息"，然后点击"仍要运行"。本安装包开源，代码可在 GitHub 上查看。
  • 如果"仍要运行"按钮不出现：右键点击 .cmd 文件 → "属性" → 勾选"解除锁定" → "确定"，然后重新双击。

Windows — zip 没有完整解压

  • 现象：双击 .cmd 后提示"找不到 install-xxx.ps1"或"系统找不到指定的路径"。
  • 原因：Windows 自带的 zip 预览功能允许不完整解压。你可能只提取了部分文件。
  • 解决方法：右键 zip 文件 → "全部解压缩" → 选择目标文件夹 → 确保"完成时显示提取的文件"已勾选 → 点击"提取"。
  • 验证：解压后打开 windows 文件夹，确认里面有 6 个文件（3 个 .cmd + 3 个 .ps1）。

Windows — PowerShell 执行策略 / npm.ps1 cannot be loaded

  • 现象：安装过程中出现红色报错，包含 npm.ps1 cannot be loaded 或 因为在此系统上禁止运行脚本。
  • 原因：Windows PowerShell 默认执行策略禁止运行 .ps1 脚本。
  • 本安装包已解决此问题：安装脚本内置了执行策略处理和 npm.cmd 优先调用。
  • 如果仍然出现：
    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
    然后重新双击 .cmd 文件。此设置仅当前窗口有效，关闭后自动失效。

Windows — 安装过程中下载依赖失败

  • 本安装包已内置安装脚本，但安装过程仍需网络（用于下载 Node.js、Agent 工具等依赖）。
  • 检查网络连接：确保电脑能正常上网。公司/学校 Wi-Fi 可能屏蔽了 npm 或 GitHub。
  • 切换网络策略：关闭代理、开启代理、手机热点、家庭网络均可尝试。不同网络环境对 GitHub / npm 的连通性不同。
  • 换个网络环境：比如从公司网络切换到家庭 Wi-Fi 或手机热点。
  • 关闭防火墙 / 安全软件：部分安全软件会拦截安装脚本的网络请求。暂时关闭后再试。
  • 等待 2–3 分钟：首次安装需要下载文件，请耐心等待。

Windows — Node.js 安装失败

  • 现象：安装脚本在"安装 Node.js"步骤卡住或报错。
  • 脚本通过 winget 自动安装 Node.js。如果 winget 不可用或卡住：
  • 手动安装 Node.js：访问 https://nodejs.org，下载左侧推荐的 LTS 版本（.msi 安装包），双击安装。安装完成后重新运行 .cmd。
  • 检查 Node.js 版本：
    node -v
    Codex 需要 ≥ v22，OpenClaw 需要 ≥ v22.19（推荐 v24+）。Claude Code 自带运行时，不需要 Node.js。

Windows — winget 卡住或不可用

  • 现象：安装脚本调用 winget 时长时间无响应。
  • 原因：winget 在某些 Windows 版本上可能未安装或版本过旧。
  • 解决方法：跳过 winget，手动安装 Node.js（见上一节"Node.js 安装失败"）。
  • 或者从 Microsoft Store 更新 winget：搜索"应用安装程序"并更新。

Windows — 安装后找不到命令（command not found）

  • 第一步：关闭 PowerShell 窗口，重新打开。这是最常见的问题——安装成功但 PATH 未立即生效。
  • 在 PowerShell 中检查：
    Get-Command claude # Claude Code Get-Command codex # Codex Get-Command openclaw # OpenClaw
  • 如果仍然找不到：重新运行安装 .cmd 即可。

macOS / Linux — bash install-xxx.sh 找不到文件

  • 请确认已进入 mac-linux 文件夹：在终端输入 cd （cd 后面有个空格），然后把 mac-linux 文件夹拖到终端窗口，回车。
  • 验证当前目录：
    ls
    应该能看到 install-claude-code.sh、install-codex.sh、install-openclaw.sh。
  • 常见错误：在"下载"目录直接运行 bash install-codex.sh，但脚本在 mac-linux 子文件夹里。必须先 cd 进去。

macOS / Linux — Permission denied

  • 现象：运行 bash install-xxx.sh 时提示 Permission denied。
  • 解决方法：
    chmod +x install-claude-code.sh chmod +x install-codex.sh chmod +x install-openclaw.sh bash install-claude-code.sh
    把最后一行换成你要安装的 Agent 对应的脚本名。不要一次复制多行。每行是一条独立命令，复制一行粘贴一行。
  • 不要用 sudo：在 Mac/Linux 上，不要用 sudo bash install-xxx.sh。

macOS / Linux — 安装过程中下载失败

  • 本安装包已内置安装脚本，但安装过程仍需网络（用于下载 Node.js、Agent 工具等依赖）。
  • 检查网络连接：确保电脑能正常上网。公司/学校 Wi-Fi 可能屏蔽了 npm 或 GitHub。
  • 切换网络策略：关闭代理、开启代理、手机热点、家庭网络均可尝试。不同网络环境对 GitHub / npm 的连通性不同。
  • 换个网络环境：比如从公司网络切换到家庭 Wi-Fi 或手机热点。
  • 等待 2–3 分钟：首次安装需要下载文件，请耐心等待，不要关闭终端窗口。

macOS / Linux — Node.js / npm 安装失败

  • Claude Code：自带运行时，不需要 Node.js。
  • Codex：需要 Node.js ≥ v22。脚本会自动检查和安装。
  • OpenClaw：需要 Node.js ≥ v22.19（推荐 v24+）。脚本会自动检查。
  • 手动检查版本：
    node -v
  • 手动安装 Node.js：访问 https://nodejs.org，下载左侧推荐的 LTS 版本安装；或使用 brew install node（Mac）。
  • npm 缓存权限异常（EACCES）：
    sudo chown -R "$(id -u):$(id -g)" "$HOME/.npm" chmod -R u+rwX "$HOME/.npm" npm cache verify

macOS / Linux — 安装后 command not found

  • 第一步：关闭终端，重新打开。安装成功但 PATH 未立即生效。
  • 检查是否已安装：
    which claude # Claude Code which codex # Codex which openclaw # OpenClaw
    如果有输出路径但运行报错，说明 PATH 问题。关掉终端重新打开。
  • 如果仍然找不到命令：重新运行安装脚本即可。
  • Mac 额外步骤：某些 Mac 可能需要先允许终端访问"开发工具"。系统提示时点"允许"即可。

普通模式会自动 fallback 吗？

  • 会自动 fallback。普通模式（不加 --china / -China）会按以下顺序自动尝试：
  • 路径 1：官方安装器（claude.ai / chatgpt.com / openclaw.ai）
  • 路径 2（自动 fallback）：npm 官方源（registry.npmjs.org）
  • 路径 3（自动 fallback）：npm 国内镜像（registry.npmmirror.com）
  • 全部不可达时：会给出网络排查建议 + 日志路径。
  • 也就是说：默认双击 .cmd 或运行 .sh 就是普通模式。安装脚本会自动探测网络，选出可用的安装路径。大部分情况下不需要用户手动判断网络状态。

什么时候使用 China 模式（--china / -China）？

  • 普通模式已包含自动 fallback 到国内镜像。大多数情况不需要手动指定 China 模式。
  • 适用场景：当你明确知道自己的网络环境无法访问国外网站，想跳过探测直接走国内镜像时。
  • macOS / Linux：
    bash install-claude-code.sh --china
  • Windows：在 PowerShell 中运行：
    .\install-claude-code.ps1 -China
  • （Codex / OpenClaw 同样支持 -China 参数。）
  • China 模式做了什么：跳过官方安装器，直接使用 npmmirror 安装。安装前会检测 npm 是否可用和镜像是否可达。

国内网络 — 安装日志排查

  • 安装日志记录了：安装模式、5 个端点的可达性、安装路径决策、Node/npm 版本、安装命令、错误信息、最终结果。
  • macOS / Linux：
    cat ~/agent-install-codex.log
  • Windows：
    type %TEMP%\agent-install-codex.log
  • 看日志里的 Network Probe 段落：可以确认哪些端点可达、脚本选择了哪条路径。

通用 — 安装命令没有反应 / 卡住了

  • 等待 2–3 分钟：首次安装需要下载文件，请耐心等待，不要关闭窗口。
  • 检查网络：公司或学校 Wi-Fi 可能屏蔽了 GitHub / npm 等网站。尝试切换手机热点再试。
  • 切换网络策略：关闭代理、开启代理、手机热点、家庭网络均可尝试。不同网络环境对 GitHub / npm 的连通性不同。
  • 按 Ctrl+C 取消后重试：偶尔网络波动会导致下载中断，重新运行安装命令即可。

Claude Code — DeepSeek API 配置问题

  • Claude Code 已安装，但 DeepSeek API 配置失败：关掉终端重新打开（环境变量需新窗口才能加载），再试 claude。
  • DeepSeek API Key 粘贴后没反应：输入 Key 时光标不会移动是正常的（安全输入模式），粘贴后直接回车即可。
  • Claude Code 启动后仍提示 Anthropic / Claude 登录：说明环境变量未生效。确认 ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic 已设置。Mac/Linux 用户运行 source ~/.zshrc 然后重试。
  • 如何手动重新配置：重新运行安装脚本，或手动设置 ANTHROPIC_BASE_URL 和 ANTHROPIC_AUTH_TOKEN 环境变量。

Codex — 登录 / API Key 问题

  • Codex 官方网页登录失败：确认 ChatGPT 账号有 Plus/Pro/Team 订阅。免费版不支持 Codex。
  • API Key 登录失败：确认 OPENAI_API_KEY 环境变量已正确设置。Key 以 sk- 开头。
  • API Key 已设置但 Codex 不识别：关掉终端重新打开（环境变量需新窗口加载）。
  • API Key 提示余额不足：登录 platform.openai.com 检查用量和余额。

OpenClaw — EACCES / permission denied

  • 现象：npm error EACCES: permission denied，路径里出现 ~/.npm/_cacache。
  • 原因：npm 缓存目录权限异常，通常是以前用 sudo npm 导致文件不属于当前用户。
  • macOS / Linux 修复：
    sudo chown -R "$(id -u):$(id -g)" "$HOME/.npm" chmod -R u+rwX "$HOME/.npm" npm cache verify npm install -g openclaw@latest --registry=https://registry.npmjs.org/ --no-audit --no-fund
  • Windows：以管理员身份运行 PowerShell：
    npm cache clean --force npm install -g openclaw@latest --registry=https://registry.npmjs.org/ --no-audit --no-fund

OpenClaw — DeepSeek 配置问题

  • 安装阶段不需要 API Key。首次使用时推荐 DeepSeek API Key。
  • 配置命令：
    openclaw onboard --auth-choice deepseek-api-key
    按终端提示输入你的 DeepSeek API Key（在 platform.deepseek.com 注册获取）。
  • 验证：
    openclaw models list --provider deepseek

安装故障排查

遇到问题了？按下面的错误类型找到对应解决方法

命令没有反应 / 卡住了

  • 等待 2–3 分钟：首次安装需要下载文件，请耐心等待，不要关闭窗口。
  • 检查网络：公司或学校 Wi-Fi 可能屏蔽了 GitHub / npm 等网站。尝试切换手机热点再试。
  • 关闭代理 / VPN：如果你开了 VPN 或代理，先关闭后再试一次。
  • 按 Ctrl+C 取消后重试：偶尔网络波动会导致下载中断，重新运行安装命令即可。
  • 换个网络环境：比如从公司网络切换到家庭 Wi-Fi 或手机热点。

下载失败（curl / iwr 报错）

  • macOS / Linux：确认命令以 curl -fsSL 开头，不要漏掉 -fsSL 参数。
  • Windows PowerShell：确认命令以 iwr -useb 开头。
  • 确保命令完整复制：整行命令从网页上完整复制，不要手动输入（容易打错）。
  • 关闭防火墙 / 安全软件：部分安全软件会拦截来自 Internet 的脚本。暂时关闭后再试。
  • 如果反复失败：可能是 jsDelivr CDN 被运营商限制。尝试切换手机热点。

权限错误（Permission denied / EACCES）

  • macOS / Linux：安装过程中如果遇到 Permission denied，脚本会自动尝试修复 npm 权限。按照提示选择 "Y" 即可。
  • macOS 额外步骤：某些 Mac 可能需要先允许终端访问"开发工具"。系统提示时点"允许"即可。
  • Windows：右键点击 PowerShell 图标 → 选择"以管理员身份运行"，然后重新执行安装命令。
  • 不要用 sudo：在 Mac/Linux 上，不要用 sudo npm install -g。如果脚本自动安装失败，重启终端再试一次。

找不到命令（command not found / 无法识别）

  • 第一步：关闭终端 / PowerShell 窗口，重新打开。这是最常见的问题——安装成功但 PATH 未立即生效。
  • macOS / Linux：
    # 检查是否已安装（在终端粘贴运行） which claude # Claude Code which codex # Codex which openclaw # OpenClaw
    如果有输出路径但运行报错，说明 PATH 问题。关掉终端重新打开。
  • Windows：
    # 在 PowerShell 中检查 Get-Command claude # Claude Code Get-Command codex # Codex Get-Command openclaw # OpenClaw
  • 重新运行安装脚本：如果关闭重开终端后依然找不到命令，重新运行安装脚本，它会识别已有安装并尝试修复。
  • 手动添加 PATH （macOS/Linux 进阶）：如果 npm 安装在自定义目录，需将该目录的 bin/ 子目录加入 PATH。

Node.js 版本问题

  • Claude Code：自带运行时，不需要 Node.js。如果遇到 node 相关报错，可能是其他软件冲突。
  • Codex：需要 Node.js >= 22。安装脚本会自动检查和安装，但如果你手动跳过，请访问 nodejs.org 下载 LTS 版本。
  • OpenClaw：需要 Node.js >= 22.19（推荐 24+）。同样会由脚本自动安装。
  • 检查当前版本：
    node -v
    如果版本号小于 v22.0.0，则需要升级 Node.js。
  • 手动安装 Node.js：访问 https://nodejs.org，下载左侧推荐的 LTS 版本安装。

PowerShell 执行策略阻止（Windows）

  • 现象：看到红色报错文字，包含 running scripts is disabled 或 PSSecurityException。
  • 解决方法（二选一）：
    # 方法 1（推荐）：仅本次跳过限制 powershell -ExecutionPolicy Bypass -File .\install-xxx.ps1 # 方法 2：永久修改执行策略 Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
  • 如果以上方法仍被阻止：可能是公司 IT 策略锁定了执行策略，请联系公司 IT 管理员申请权限。

Windows 报错：npm.ps1 cannot be loaded because running scripts is disabled

  • 现象：安装过程中出现红色报错，包含 npm.ps1 cannot be loaded 或 UnauthorizedAccess，提示 因为在此系统上禁止运行脚本。
  • 原因：Windows PowerShell 默认执行策略可能禁止运行 .ps1 脚本。旧版本脚本直接调用 npm 时，PowerShell 可能会优先解析到 C:\Program Files\nodejs\npm.ps1，从而被系统拦截。
  • 推荐解决方案：升级到 v3.0.8 或更新版本。新版脚本会优先调用 npm.cmd，避免触发 npm.ps1 执行策略问题。
    # 使用最新版安装命令（已内置 npm.cmd 优先调用） iwr -useb https://cdn.jsdelivr.net/gh/vinnim92/agent-install-guide@v3.0.8/scripts/install-codex.ps1 | iex
  • 临时解决方案（如果暂时不想升级）：
    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
    然后重新运行安装命令。这个设置只对当前 PowerShell 窗口有效，关闭窗口后自动失效，不会影响系统安全策略。
  • 说明：不推荐使用 Set-ExecutionPolicy RemoteSigned -Scope CurrentUser 永久修改策略。新版脚本优先使用 npm.cmd 从根本上避免此问题。

Claude Code — DeepSeek API 配置问题

  • Claude Code 已安装，但 DeepSeek API 配置失败：关掉终端重新打开（环境变量需新窗口才能加载），再试 claude。如果仍不生效，检查 ~/.zshrc（Mac/Linux）或系统环境变量（Windows）中是否正确写入了 ANTHROPIC_BASE_URL 和 ANTHROPIC_AUTH_TOKEN。
  • DeepSeek API Key 粘贴后没反应：输入 Key 时光标不会移动是正常的（安全输入模式），粘贴后直接回车即可。如果粘贴失败，右键粘贴后再按回车。
  • Claude Code 启动后仍提示 Anthropic / Claude 登录：说明环境变量未生效。确认 ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic 已设置。Mac/Linux 用户运行 source ~/.zshrc 然后重试。
  • 如何手动重新配置 DeepSeek：重新运行安装脚本，或参考 Claude Code 教程 手动设置环境变量。

Codex — API Key 登录问题

  • Codex 官方网页登录失败：确认 ChatGPT 账号有 Plus/Pro/Team 订阅。免费版不支持 Codex。尝试手动运行 codex login。
  • Codex API Key 登录失败：确认 OPENAI_API_KEY 环境变量已正确设置。Mac/Linux 用 echo $OPENAI_API_KEY 检查，Windows 用 $env:OPENAI_API_KEY 检查。Key 以 sk- 开头。
  • OPENAI_API_KEY 已设置但 Codex 不识别：关掉终端重新打开（环境变量需新窗口加载）。或用 printenv OPENAI_API_KEY | codex login --with-api-key（Mac）/ $env:OPENAI_API_KEY | codex login --with-api-key（Windows）直接传递。
  • API Key 提示余额不足：登录 platform.openai.com 检查 API 用量和余额。

运行到"是否继续安装"时，直接显示已取消

  • 原因：使用 curl | bash 时，脚本的标准输入来自 curl 管道，有时无法从键盘读取确认输入。
  • 解决方法一（推荐）：使用交付包中的自动确认命令：
    curl -fsSL "https://cdn.jsdelivr.net/gh/vinnim92/agent-install-guide@v3.0.8/scripts/install-openclaw.sh" | AGENT_INSTALL_YES=1 bash
    把命令中的脚本名换成你要安装的 Agent（install-claude-code.sh / install-codex.sh / install-openclaw.sh）。加上 AGENT_INSTALL_YES=1 后脚本会自动跳过确认。
  • 解决方法二：先下载脚本再运行（可以手动确认）：
    curl -fsSL "https://cdn.jsdelivr.net/gh/vinnim92/agent-install-guide@v3.0.8/scripts/install-openclaw.sh" -o install-openclaw.sh bash install-openclaw.sh

OpenClaw 安装失败：EACCES / permission denied / ~/.npm/_cacache

  • 现象：
    • npm error EACCES: permission denied
    • 路径里出现 ~/.npm/_cacache
    • npm view openclaw version 能返回版本号，但 npm install -g openclaw 失败
  • 原因：npm 缓存目录权限异常，通常是以前用 sudo npm 或某些安装器导致 ~/.npm 中部分文件不属于当前用户。
  • 这不是 OpenClaw 包不存在，也不是命令复制错误。
  • macOS / Linux 修复：
    sudo chown -R "$(id -u):$(id -g)" "$HOME/.npm" chmod -R u+rwX "$HOME/.npm" npm cache verify npm install -g openclaw@latest --registry=https://registry.npmjs.org/ --no-audit --no-fund
  • Windows：以管理员身份运行 PowerShell，然后：
    npm cache clean --force npm install -g openclaw@latest --registry=https://registry.npmjs.org/ --no-audit --no-fund
  • 兜底方案：如果修复后仍失败，备份并重建 npm 缓存目录：
    mv "$HOME/.npm" "$HOME/.npm.bak.$(date +%Y%m%d_%H%M%S)" npm install -g openclaw@latest --registry=https://registry.npmjs.org/ --no-audit --no-fund

OpenClaw 提示 OpenAI Codex OAuth failed unsupported_region

  • 现象：OpenClaw 安装成功，但执行 OpenAI Codex OAuth 登录时报错：OpenAI Codex OAuth failed (unsupported_region)
  • 原因：这是 OpenAI Codex OAuth 在当前国家、地区或网络路线下无法完成认证，不是 OpenClaw 安装失败。
  • 推荐解决：大陆用户建议使用 DeepSeek API Key：
    openclaw onboard --auth-choice deepseek-api-key
  • 验证：
    openclaw models list --provider deepseek
  • 说明：如果你确实要使用 OpenAI Codex OAuth，需要自行确认所在网络和账号是否支持；本安装包不提供绕过地区限制的方法。

OpenClaw 首次配置

  • 安装阶段不需要 API Key。首次配置或正式使用时，推荐使用 DeepSeek API Key（国内获取方便、价格便宜）。
  • 配置命令：
    openclaw onboard --auth-choice deepseek-api-key
    按终端提示输入你的 DeepSeek API Key（在 platform.deepseek.com 注册获取）。
  • 验证：
    openclaw models list --provider deepseek
  • 启动控制面板：
    openclaw dashboard

登录失败 / 认证失败（通用）

  • OpenClaw：推荐使用 DeepSeek API Key 方案。运行 openclaw onboard --auth-choice deepseek-api-key 按提示配置。
  • 浏览器没有弹出？手动在浏览器中打开对应网址登录，然后回到终端重试。
  • 登录后仍然提示未授权？确认你的账号订阅状态有效。如果刚购买 Plus/Pro，等几分钟后再试。
通用排查思路：
1. 关掉终端 → 重新打开 → 重试
2. 切换网络（手机热点）→ 重试
3. 重启电脑 → 重试
4. 大部分安装问题都可以通过以上三步解决。
